# {{ page.title }}

Основной набор команд общий для всех трёх платформ: сборка `AmneziaGeo.Cli`, а поверх неё тонкий хост под каждую систему. Его дополняют команды отдельных платформ, например режим нескольких VPN на Windows. Всё идёт через агента по протоколу `IpcContract`, базу консоль не трогает - поэтому её правки сразу видят и агент, и интерфейс.

## Запуск
{% if page.device == "windows" %}
`amneziageo.exe <команда>` из `%ProgramFiles%\AmneziaGeo`.
{% elsif page.device == "linux" %}
`amneziageo <команда>`
{% elsif page.device == "android" %}
```text
adb shell am broadcast -a org.amneziageo.android.CLI -n org.amneziageo.android/.CliReceiver --es cmd "<команда>"
```

Ответ приходит в `data=` той же команды `adb`, целиком дублируется в logcat под тегом `AmneziaGeoCli`, а с `--es out <путь>` пишется в файл. Аргументы с дефисами передавайте массивом: `--esa args ops,--probe`. Приёмник закрыт разрешением `android.permission.DUMP`: оно есть у `adb shell` и его не получает обычное приложение. Интерфейс поднимать не нужно - приёмник запускает агента в своём процессе. Команде `up` нужно разрешение на VPN, которое система спрашивает один раз в окне приложения.
{% endif %}

## Повседневное

```bash
amneziageo status                   # что работает и что возьмёт следующее подключение
amneziageo doctor                   # проверки, на которых обычно спотыкается установка
amneziageo runtime                  # конфигурация, которую возьмёт следующее подключение
amneziageo --json config list       # вывод для скриптов
amneziageo sessions --filter youtube # каждый адрес, который решает туннель, и почему
amneziageo log tail --level info
amneziageo tui                      # полноэкранная консоль по SSH
```

`amneziageo help` перечисляет все команды.

## Справочник команд

Глобальные ключи стоят перед командой: `--json` - JSON вместо таблиц, `--lang en|ru` - язык вывода (иначе `AMNEZIAGEO_LANG`, иначе язык системы), `--timeout <с>` - сколько ждать ответа (загрузка баз требует больше), `--quiet` - только запрошенное, `--version` - версии клиента и агента, `--help`.

### Подключение

| Команда | Что делает |
|---|---|
| `status` | что работает и что возьмёт следующее подключение |
| `watch` | следить за состоянием, пока не прервут |
| `select <конфиг>` | выбрать конфигурацию для следующего подключения |
| `up [<конфиг>]` | подключиться, при необходимости сначала выбрав |
| `down` | отключиться |

### Конфигурации

| Команда | Что делает |
|---|---|
| `config list` | список; колонки INBOUND, SIGNAL и HOLD показывают переключатели конфигурации |
| `config show <имя>` | текст wg-quick |
| `config link <имя>` | ссылка `vpn://` для передачи |
| `config import [<имя>] (--file <путь> \| --link <url> \| --text <текст> \| --stdin)` | добавить; адрес `http(s)` читается как подписка |
| `config edit <имя> (--file <путь> \| --text <текст> \| --stdin)` | заменить текст |
| `config rename <имя> <новое>` | переименовать |
| `config copy <имя> <новое>` | скопировать |
| `config remove <имя>` | удалить |
| `config order <имя> [<имя>...]` | порядок в каталоге |
| `config dns <имя> [<серверы>]` | свои резолверы; без аргумента - сброс |
| `config exclusions <имя> (--file <путь> \| --stdin \| --list a,b,c \| --clear)` | адреса и подсети мимо VPN |
| `config websocket <имя> on\|off [--host <хост>] [--port <порт>] [--mtu <n>] [--ipv6 on\|off] [--router on\|off]` | транспорт WebSocket и соседние переключатели |
| `config mtu <имя> auto\|config\|<число>` | размер пакета: подобранный, из текста или заданный |
| `config inbound <имя> off\|host\|network` | входящие из VPN-сети: никто, сервер или вся сеть туннеля |
| `config routing <имя> on\|off` | применять ли к конфигурации список маршрутизации |
| `config signal <имя> on\|off` | разрешить ли серверу снимать туннель |
| `config hold <имя> on\|off` | удерживать ли трафик, пока туннель переподключается |
| `config geo <имя> on\|off [правило...]` | собственные правила раздельного туннеля конфигурации, без ролей |

### Списки маршрутизации

| Команда | Что делает |
|---|---|
| `routing list` | списки |
| `routing use <id\|имя\|none>` | выбрать список; `none` оставляет решение за `AllowedIPs` конфигурации |
| `routing show <id\|имя>` | правила списка |
| `routing create <имя> [правило...]` | создать |
| `routing set <id\|имя> [правило...]` | заменить все правила |
| `routing add <id\|имя> <правило...>` | добавить; правило, которое уже есть, получает новую роль |
| `routing delete-rule <id\|имя> <правило...>` | удалить правила |
| `routing remove <id\|имя>` | удалить список |
| `routing update <id\|имя>` | взять новую версию списка, которую прислал его сервер |
| `routing order <имя> [<имя>...]` | порядок в разделе |
| `routing settings <id\|имя>` | настройки трафика |
| `routing configure <id\|имя> [--exclusions <a,b>] [--exclusions-file <путь>] [--all-udp on\|off] [--global-proxy on\|off]` | исключения, весь UDP через туннель, полный туннель |

Правило - `<роль>|<запись>`: роль `proxy`, `direct` или `block`, запись `geosite:<категория>`, `geoip:<страна>`, `domain:<имя>`, `app:<id>` либо адрес или диапазон CIDR. Запись без роли считается `proxy`.

## Несколько VPN одновременно

Используйте имена конфигураций, уже добавленных в клиент. Например, для `office` и `personal`:

```powershell
amneziageo settings set multi-server on
amneziageo fleet up office
amneziageo fleet up personal
amneziageo fleet primary office
amneziageo fleet role personal reserve
amneziageo fleet status
amneziageo fleet down personal
```

Чтобы выбрать сервер и запасной маршрут для существующего прокси-правила списка:

```text
amneziageo fleet target <id-или-имя-списка> <правило> <сервер-или-auto-best-direct-block> [запасной-маршрут]
```

Например, если правило `domain:example.com` уже добавлено в список `sites` с ролью «прокси»:

```powershell
amneziageo fleet target sites domain:example.com personal office
```

`fleet up` добавляет одно подключение, с `--takeover` - забирает туннель, поднятый под другой учётной записью, а `fleet down` отключает указанный сервер. `fleet role <конфиг> primary|reserve|neutral` задаёт роль, `fleet slot <конфиг> <место>` - место среди резервных, `fleet order` - их порядок. Режим и команды `fleet` сейчас доступны только на Windows.

## Полноэкранная консоль

`amneziageo tui` - полноэкранный интерфейс консольного клиента, в том числе по SSH. Слева рейка разделов, справа панель раздела.

- «Состояние»: туннель подключён или отключён, выбранная конфигурация, список маршрутизации, последняя ошибка; кнопки «Подключить», «Отключить», «Обновить».
- «Конфигурации»: «Выбрать», «Показать» текст, «Импорт» - одно поле на конфигурацию wg-quick, ссылку `vpn://` или адрес `http(s)`, который агент читает как подписку, «Ссылка» - ссылка `vpn://` конфигурации, «Удалить».
- «Маршрутизация»: «Выбрать» список, «Отключить» маршрутизацию, «Правила…» - редактор, одно правило в строке: `proxy|geosite:x`, `direct|geoip:ru`, `block|domain:y`, «Параметры…» - «Весь UDP через туннель» и исключения, «Удалить».
- «Источники geo»: «Обновить все» и удаление базы.
- «Общие»: уровень журнала, «Восстанавливать после перезагрузки», «Переподключаться автоматически», «Интервал повтора», «Записывать подключения в журнал».
- «Диагностика»: журнал агента с поиском и очисткой.

Клавиши: стрелки или Tab - переход между панелями и элементами, Enter - нажать, F10 - выход; Esc консоль не закрывает. Ctrl+V вставляет из буфера обмена через `wl-paste`, `xclip` или `xsel`; без них вставляйте сочетанием самого терминала, Ctrl+Shift+V.
{% endif %}

## Отладка

```bash
amneziageo log say "начало прогона" # отметка в журнале агента
amneziageo ops                      # операции протокола и команды, которые их вызывают
amneziageo ops --probe              # какие операции реализует агент этой платформы
amneziageo ipc <операция> [арг...]  # вызвать любую операцию напрямую
```

`ops --probe` шлёт каждую операцию без аргументов: отказ от её обработчика значит, что операция есть, а отказ диспетчера - что её нет. Операции, которые без аргументов сделали бы работу по-настоящему - подключение, скачивание, удаление, - помечаются `-` и не отправляются.

Переменные окружения: `AMNEZIAGEO_LANG` - язык вывода без `--lang`, `AMNEZIAGEO_CONNECT_WAIT` - сколько секунд ждать агента (по умолчанию 5).

## Коды возврата

| Код | Что означает |
|---|---|
| 0 | готово |
| 1 | агент отказал |
| 2 | ошибка в команде |
| 3 | агент недоступен |
| 5 | операция не реализована агентом этой платформы |
